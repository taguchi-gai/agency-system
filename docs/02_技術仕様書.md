## 2. ジオコーディング API 選定

### 候補 1: Google Maps Geocoding API
**メリット**
- 精度が高い（世界中対応）
- 日本国内でも十分な精度
- ドキュメントが充実している

**デメリット**
- 有料（1,000 リクエスト/月は無料だが、超過時は有料）
- API キー管理の必要

**推奨用途**
- 本格的な事業展開時、精度を重視する場合

### 候補 2: 国土地理院 ジオコーディング API
**メリット**
- 完全無料（日本国内限定）
- 官公庁提供で信頼性高い
- 日本国内ならこれで十分な精度

**デメリット**
- 日本国内のみ
- レスポンスが若干遅い場合がある

**推奨用途**
- 日本国内のみの事業ならコスト最適

### 候補 3: OpenStreetMap Nominatim
**メリット**
- 完全無料
- 世界中対応
- 自社サーバーで運用可能

**デメリット**
- 精度が Google より低い（地方は特に）
- 利用規約で過度な利用が禁止

**推奨用途**
- 初期段階でコストをかけたくない場合

**→ 推奨：国土地理院 API（コスト最適で精度も十分）**

## 5.5 貴重品確認の電子署名データ保存（本番化時）

モックでは「貴重品確認」を、施工現場でお客さまがタブレット/スマホの画面に手書き署名し、
送信すると同時に本部にも記録が残る形で実装している（施工代理店の自己申告だけで
ステータスを進められないようにするための証跡）。本番では署名画像をブラウザの
メモリ内に留めず、以下の方針でサーバー側に保存する。

### 保存方針
- 署名は Canvas から `toDataURL()` で PNG 化せず、**送信時にファイルとして S3 等のオブジェクトストレージにアップロード**する（DBには直接バイナリを入れない）
- **改ざん防止のため、以下をセットで記録する**：
  - 署名画像ファイル（PNG）
  - 送信時刻のサーバー側タイムスタンプ（クライアントの時刻は信用しない）
  - 送信元の施工代理店ID（ログイン中のセッションから取得。クライアントが偽装できない形にする）
  - 案件番号（service_order_id）との紐付け
  - 署名画像のハッシュ値（SHA-256等）をDBに保存し、後から画像が差し替えられていないか検証できるようにする
- 一度送信された署名データは**更新・削除不可**（訂正が必要な場合は新しい確認を取り直す運用とし、履歴として両方残す）

### テーブル案（valuables_confirmations）
```sql
CREATE TABLE valuables_confirmations (
  id INT PRIMARY KEY AUTO_INCREMENT,
  service_order_id VARCHAR(20) NOT NULL,
  contractor_id INT NOT NULL,           -- 送信元の施工代理店（セッションから取得、クライアント指定不可）
  signature_file_url VARCHAR(500) NOT NULL,  -- S3等のオブジェクトストレージURL
  signature_hash VARCHAR(64) NOT NULL,       -- SHA-256ハッシュ（改ざん検知用）
  confirmed_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP, -- サーバー側の受信時刻
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (service_order_id) REFERENCES service_orders(id),
  FOREIGN KEY (contractor_id) REFERENCES contractors(id)
);
CREATE INDEX idx_valuables_confirmations_order ON valuables_confirmations(service_order_id);
```

### API案
```
POST /api/service-orders/{id}/valuables-confirmation
リクエスト（multipart/form-data）:
  signature_image: (PNGファイル)

サーバー側処理:
  - 認証中の施工代理店IDをセッションから取得（クライアントからは受け取らない）
  - 画像をS3にアップロード
  - SHA-256ハッシュを計算してDBに保存
  - confirmed_at はサーバー時刻を使用
  - service_orders.status を「貴重品確認済み」に更新
```

from fastapi_mail import FastMail, MessageSchema

## 8. セキュリティ考慮事項

- **API キー管理**：環境変数に格納、Git に含めない
- **認証**：JWT トークンベースの認証
- **HTTPS**：全通信を暗号化
- **レート制限**：ジオコーディング API への過度なアクセスを防止
- **ユーザー権限**：本部・加盟店・施工代理店で参照可能なデータを分離

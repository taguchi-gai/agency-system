# 代理店管理システム - プロジェクトドキュメント

## 📁 このフォルダについて

このフォルダ（`docs/`）には、**モック HTML から本番システムへの開発を進めるための設計書・要件書**が格納されています。

## 📄 ドキュメント一覧

### 1. **01_機能要件書.md**
**内容**：地理的マッチング機能（半径検索・自動割り当て・通知）の詳細要件

**対象者**：営業・プロダクトマネージャー、開発チーム全体

**主な内容**：
- 機能概要
- 詳細要件（入力・計算・マッチング・通知）
- データベーススキーマ追加案
- 実装フェーズ（Phase 1～4）

**確認すべき項目**：
- [ ] 半径 5km / 10km / 15km など、チューニング値は適切か？
- [ ] メール通知のタイミング・内容は要望に合っているか？
- [ ] 位置情報の精度（±100m～±500m）で十分か？

### 2. **02_技術仕様書.md**
**内容**：実装方針・API 設計・インフラ構成・テスト計画

**対象者**：開発チーム（バックエンド・フロントエンド・DevOps）

**主な内容**：
- システムアーキテクチャ
- ジオコーディング API 選定（Google / 国土地理院 / OSM）
- バックエンド実装方針（Python + FastAPI / Node.js + Express）
- REST API 仕様
- データベーススキーマ詳細
- 本番インフラ構成（AWS / Vercel + Firebase）
- セキュリティ考慮事項

**確認すべき項目**：
- [ ] ジオコーディング API は国土地理院で決定か？
- [ ] バックエンド言語・フレームワークは Python/FastAPI か？
- [ ] Vercel + Firebase で本番化するか？それとも AWS か？
- [ ] メール配信サービスは SendGrid か SES か？

**モック HTML の役割**：
- ✅ 4 層構造（本部・加盟店・取次店・施工代理店）の UI 設計確認済み
- ✅ ユーザーフロー（注文 → 割り当て → 完了）の検証済み
- ❌ データベース・バックエンド・リアルタイム機能は未実装

**本番開発では**：
- モック HTML をベースに React / Vue.js で再実装
- バックエンド（Python/Node.js）を新規開発
- ジオコーディング・距離計算・通知機能を追加
